# 機能仕様 06: UX改善 と ファイル取り込み

## 背景
- 読み取り結果に長いURL等の技術文字列が露出し、一般利用者には意味不明
- 資格者証はPDFで配布されるため、カメラだけでなくPDF/画像から直接QRを読みたい

## US-15: 技術情報の折りたたみ
- 読み取り結果の生URL・署名検証バッジ等の技術情報は既定で隠し、
  「🔧 技術情報を表示」を押したときだけ展開する
- 人が見て意味のある「検出ステータス」「登録情報」「公式検証結果」は常時表示

### 受入条件
- [ ] 生URL文字列は既定で非表示、details/summaryで開閉できる
- [ ] 署名検証バッジ（技術寄り）も技術情報内にまとめる
- [ ] 登録情報テーブルと公式検証結果は折りたたまず表示

## US-16: PDF/画像ファイルからのQR読み取り
- スキャン画面に「📄 ファイルから読み取り」を追加
- PDF（複数ページ対応）・画像（PNG/JPG）を選択するとQRをデコードし、
  カメラ読み取りと同じ結果フローに乗せる

### 受入条件
- [ ] PDFを選ぶと各ページを描画してQRを探索、最初に見つかったQRを採用
- [ ] 画像を選ぶと描画してQRをデコード
- [ ] QRが見つからない場合は分かりやすいエラー表示
- [ ] 取り込み処理中はローディング表示、UIをブロックしない
- [ ] 取り込みはオフラインでも動作（pdf.js等はバンドル）

## 技術仕様
- PDF描画: `pdfjs-dist`（Vite で worker を `?url` インポート）。
  ページを canvas に十分な解像度（目標幅 ~2000px、見つからなければ拡大して再試行）で描画し、
  `jsQR` で ImageData を走査。
- 画像: `createImageBitmap` → canvas → `jsQR`。
- 既存の `handleDetected(data)` を共通エントリにして結果表示・履歴・公式検証へ繋ぐ。

## スコープ外
- 複数QRの同時検出（最初の1件のみ）
- PDF内の画像抽出最適化（ページ描画方式で十分）
