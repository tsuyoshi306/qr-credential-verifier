# 機能仕様 04: アプリ内 署名検証・登録情報表示

## 背景
従来は検証サイト（dqcvs.nqs.go.jp）へ遷移させる設計だったが、ユーザー要望により
**アプリ内でQRの署名済みデータ（COSE）を解析し、登録情報の表示と署名検証を行う**方針へ変更。
ただし constitution 原則 1.5 の通り、失効・取消照会は不可能であり「有効」の断定表示はしない。

## QRデータ構造（実物解析で確定 / 小型船舶操縦士の資格者証, 2026-06）
```
https://dqcvs.nqs.go.jp/w/?c=<base64url>
```
- `c=` パラメータ = 登録情報（署名済み）の base64url
- デコード結果 = **COSE_Sign1（CBOR tag 18）** の4要素配列
  - protected: `{1: -37}` → **alg = PS256（RSA-2048 / RSASSA-PSS, SHA-256）**
  - unprotected: `{4: "P-000001"}` → **kid のみ。署名証明書(x5chain)は同梱されない**
  - payload: CBOR map。実キー（2文字コード）:
    - `CN`=資格名称, `UN`=氏名, `UB`=生年月日, `RN`=登録番号, `RD`=登録年月日,
      `ID`=発行年月日, `IA`=交付機関, `IN`=交付者名, `CI`=資格ID,
      `DN`=証明書ID, `DT`=種別コード, `UC`=利用者コード
  - signature: 256バイト（RSA-2048）

## 重大な制約（実物調査で確定）
- 署名証明書はQRに**含まれず**、`kid="P-000001"` で外部の鍵を参照する設計
- その公開鍵は**一般公開されていない**（検証サイトがサーバ側で保持し「検証実施」POSTで検証）
- よって**アプリ単独での署名検証は現状不可能**。コードはPS256検証に対応済みで、
  公開鍵が入手でき次第 `src/trust-config.js` にJWK(kid="P-000001")を追加すれば有効化される
- 実物QRの署名バッジは「🔒 署名検証スキップ（公開鍵未設定）」となる（正しい挙動）

## ユーザーストーリー
- **US-09**: 検証サイトに行かず、QRに含まれる登録情報（氏名・資格名・登録番号等）をアプリ内で確認したい
- **US-10**: 署名が改竄されていないか（公開鍵がある場合）アプリ内で検証したい
- **US-11**: アプリの検証だけでは不十分なこと（失効未確認）を明確に理解したい

## 受入条件
- [ ] QRが `dqcvs.nqs.go.jp/w/?c=...` のとき、`c=` を取り出して Base64(url) デコードできる
- [ ] デコード結果を CBOR/COSE_Sign1 としてパースし、payload（登録情報）を取り出して**表示**する
- [ ] payload が CBOR map の場合、キー・値を一覧表示する（既知キーは日本語ラベルに変換）
- [ ] protected ヘッダから署名アルゴリズムを表示する
- [ ] **公開鍵が設定されている場合**: COSE_Sign1 の署名を Web Crypto API で検証し、結果（OK/NG）を表示する
- [ ] **公開鍵が未設定の場合**: 「署名検証: 公開鍵が未設定のためスキップ」と表示する（エラーにしない）
- [ ] いかなる場合も「✓有効」とは表示せず、「失効・取消状態は未確認」「公式確認は検証サイトで」の注意書きを常に表示する
- [ ] COSEパースに失敗した場合は生データ表示にフォールバックし、エラーメッセージを出す
- [ ] パース結果（登録情報・署名検証結果）を履歴に保存する

## 技術仕様

### 依存ライブラリ
- `cbor-x`（CBOR エンコード/デコード、ブラウザ対応）
- 署名検証は **Web Crypto API**（`crypto.subtle`）を使用。外部ライブラリ不要。

### COSE_Sign1 署名検証手順（ES256想定）
1. COSE_Sign1 を `[protected, unprotected, payload, signature]` に分解
2. `Sig_structure = ["Signature1", protected, h'' (external_aad), payload]` を構築
3. `Sig_structure` を CBOR エンコード → 検証対象バイト列
4. 公開鍵（P-256, JWK）を `crypto.subtle.importKey`
5. `crypto.subtle.verify({name:'ECDSA', hash:'SHA-256'}, key, signature, sigStructureBytes)`

### 公開鍵の差し込み（プラガブル設計）
- `src/trust-config.js` に公開鍵（JWK配列）を定義する
- デフォルトは空配列（＝署名検証スキップ）
- デジタル庁が公開鍵/トラストリストを公表した場合、ここに追記すれば検証が有効化される
- 鍵の取得元・kid のメモもこのファイルに記載

### 既知payloadキーのラベル（暫定・サンプル前提）
実データのCBORキー定義が未公表のため、文字列キー・数値キーの両対応で汎用表示する。
判明している表示項目（PDF p.5）: 資格名称 / 氏名 / 生年月日 / 登録番号 / 発行日 / 交付機関。

## UI仕様
- スキャン後、`dqcvs.nqs.go.jp/w/?c=` を検出したら「資格者証QRを検出」表示
- 「📋 登録情報を表示」ボタン → パースして登録情報カードを表示
- 署名検証結果バッジ:
  - 鍵あり・検証OK: 「🔏 署名OK（改竄なし）」（緑）＋「※失効状態は未確認」
  - 鍵あり・検証NG: 「⛔ 署名検証に失敗（改竄の疑い）」（赤）
  - 鍵なし: 「🔒 署名検証スキップ（公開鍵未設定）」（グレー）
- 常時表示の注意書き: 「公式な有効性確認はデジタル庁の検証サイトで行ってください」＋検証サイトを開くボタンも残す
