# プロジェクト原則（Constitution）

## ミッション
デジタル資格者証のQRコードを素早くスキャンし、真正性を確認できる手軽なPWAを提供する。

## 設計原則

### 1. プライバシー優先
- スキャンデータ・履歴はすべてブラウザローカル（IndexedDB）に保存
- QRの署名済みデータ（COSE）の解析・表示はブラウザ内（クライアントサイド）で行う
- 例外: 公式検証（原則1.6）を実行する場合のみ、ユーザーの明示操作で資格データを
  自前の中継サーバ経由でデジタル庁検証サイトへ送信する。第三者の公開プロキシは使わない。

### 1.5 検証の限界を誤魔化さない（最重要・安全原則）
- アプリ内（クライアント単体）でできるのは「登録情報の表示」のみ
- 署名検証は公開鍵が入手できないため不可（PS256対応コードは用意済みだが鍵が非公開）
- **失効・取消・一時停止の確認もクライアント単体では不可能**
- クライアント単体の表示では決して「✓有効」と断定しない

### 1.6 公式検証は中継サーバ経由でデジタル庁サイトに委ねる
- 真の有効性確認（署名検証＋失効・取消・一時停止）はデジタル庁検証サイト
  （dqcvs.nqs.go.jp）のみが可能
- 検証サイトはCORS不許可・X-Frame-Options:DENY のため、PWAから直接呼べない
- そこで自前の中継サーバ（Cloudflare Worker）を経由し、検証サイトの結果を
  そのままアプリに表示する。アプリは独自判断を加えず、サイトの判定結果を提示する
- これは公式APIではなくHTML解析のため、サイト仕様変更で壊れうる旨を明示する

### 2. オフライン対応
- スキャン・履歴閲覧はオフラインでも動作する（PWA）
- 検証リンクへの遷移のみオンライン必須

### 3. スマホファースト
- タッチ操作前提のUI
- カメラ権限要求は初回スキャン時のみ

### 4. シンプルさ優先
- 不要な依存ライブラリを追加しない
- フレームワーク（React等）は使わない

## スコープ外（やらないこと）
- 失効・取消・一時停止の照会（非公開APIが必須のため原理的に不可）
- アプリ内での「有効」の断定表示（安全上禁止。原則1.5参照）
- ユーザーアカウント・ログイン
- サーバーサイドの実装
- iOS/Androidネイティブアプリ化

## 技術仕様メモ（デジタル庁 公式資料 2025-11-04版 p.7 より）
QRコードの中身:
```
https://dqcvs.nqs.go.jp/w/?c=<登録情報（署名済み）のBase64>
```
- `c=` の値 = COSE形式（CBOR署名付きデータ, RFC 8152）
  - ① 登録情報・識別情報（氏名・資格名・登録番号など）
  - ② ①に対する署名値
- 検証サイト側の処理: 署名検証 + 有効性照会（国家資格システム） + 証明書失効照会（認証局）
