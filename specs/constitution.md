# プロジェクト原則（Constitution）

## ミッション
デジタル資格者証のQRコードを素早くスキャンし、真正性を確認できる手軽なPWAを提供する。

## 設計原則

### 1. プライバシー優先
- スキャンデータはすべてブラウザローカルに保存（サーバー送信なし）
- QRの署名済みデータ（COSE）の解析・署名検証もすべてブラウザ内（クライアントサイド）で行う

### 1.5 検証の限界を誤魔化さない（最重要・安全原則）
- アプリ内でできるのは「①登録情報の表示」と「②署名による改竄検知（公開鍵がある場合）」のみ
- **失効・取消・一時停止の確認はアプリ単体では原理的に不可能**（非公開の照会APIが必須）
- したがってアプリは決して「✓有効」と断定表示しない。表示は「署名OK＝改竄なし／ただし失効状態は未確認」に留め、公式な有効性確認はデジタル庁検証サイト（dqcvs.nqs.go.jp）で行うよう必ず案内する

### 2. オフライン対応
- スキャン・履歴閲覧はオフラインでも動作する（PWA）
- 検証リンクへの遷移のみオンライン必須

### 3. スマホファースト
- タッチ操作前提のUI
- カメラ権限要求は初回スキャン時のみ

### 4. シンプルさ優先
- 不要な依存ライブラリを追加しない
- フレームワーク（React等）は使わない

## スコープ外（やらないこと）
- 失効・取消・一時停止の照会（非公開APIが必須のため原理的に不可）
- アプリ内での「有効」の断定表示（安全上禁止。原則1.5参照）
- ユーザーアカウント・ログイン
- サーバーサイドの実装
- iOS/Androidネイティブアプリ化

## 技術仕様メモ（デジタル庁 公式資料 2025-11-04版 p.7 より）
QRコードの中身:
```
https://dqcvs.nqs.go.jp/w/?c=<登録情報（署名済み）のBase64>
```
- `c=` の値 = COSE形式（CBOR署名付きデータ, RFC 8152）
  - ① 登録情報・識別情報（氏名・資格名・登録番号など）
  - ② ①に対する署名値
- 検証サイト側の処理: 署名検証 + 有効性照会（国家資格システム） + 証明書失効照会（認証局）
