# 機能仕様 08: 単一/一括 検証結果の表示統一と「詳細」展開

## 背景
一括検証の各行が公式検証の全詳細を即表示すると一覧が長くなる。一方で単一検証と
一括検証で表示項目が食い違うのは混乱を招く。両者の表示内容を完全一致させつつ、
一括ではコンパクト表示＋「詳細」展開とする。

## US-19: 表示項目の統一
- 公式検証の詳細表示（判定・確認日時・登録情報・証明書情報）は、
  単一検証と一括検証で**同一の項目・同一のレンダリング**であること
- 実装上は共通関数 `buildOfficialResultHtml(data)` を唯一の真実とする

## US-20: 一括は「詳細」展開（単一検証と同じ二段構え）
- 一括の各行は既定で**コンパクト表示**（ファイル名・資格名/氏名・署名バッジ・「詳細」ボタン）
- 「詳細」押下でまず**QRに含まれる登録情報（COSE）**を表示（単一検証の登録情報と同一項目）
- 詳細内の「🏛 公式検証」ボタン押下で**公式検証結果（判定＋登録情報＋証明書情報）を全表示**
- これは単一検証の流れ（登録情報→公式検証ボタン→公式結果）と完全に一致させる
- 「全件公式検証」は各行の公式結果をまとめて取得し、詳細内に反映

## 受入条件
- [ ] 一括各行は既定コンパクト、「詳細」で開閉
- [ ] 「詳細」展開時、まずQRのCOSE登録情報を表示（単一の `cred-info` と同一項目・同一生成）
- [ ] 詳細内「公式検証」押下で公式結果を全表示（単一の `buildOfficialResultHtml()` と同一）
- [ ] 資格者証でない/エラー行は登録情報の代わりにエラーを表示し公式検証ボタンを出さない
- [ ] 「全件公式検証」で各行の詳細に公式結果が入る
- [ ] 既存のビルド・テストが通る

## スコープ外
- 単一検証側のレイアウト変更（現状維持。詳細は従来どおり直接表示）
